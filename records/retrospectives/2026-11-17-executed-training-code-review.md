## The second material issue: exact anchors do not qualify the derivative

`NativeGraph` states its approximation directly (`native_graph.py:1–11`). It retains every observed native incoming and merged tensor, reconstructs keys, values and per-layer auxiliary inputs using the Torch model, and adds the change of a connected Torch calculation to the captured native origin (`:35–51,64–95`). The frozen side is computed once; it is not recomputed to hide movement. Every layer and all three merges remain connected, including frozen transformations between editable ones.

The runner's three exact-origin checks compare all incoming and merged arrays for the reverse pass and the two JVPs (`run.py:188–280`). This catches an inconsistent origin or incomplete inventory. The equality is also the construction's defining property: native plus current-minus-frozen gives the native origin. It does **not** show that the derivative of current-minus-frozen equals a finite native weight response, nor that reconstructed cache values equal captured native cache bytes.

The Torch implementation preserves actual positions, causal attention, the sliding window, producer/shared-cache mapping, rotary structure, three-branch residual order, per-layer embeddings and layer scales (`torch_forward.py:147–245`). I checked the native Gemma4 architecture source as well. The absence of an extra query/key `1/sqrt(head_width)` factor is intentional: native `gemma4.cpp:11` sets attention scale to1. The dense FFN, third branch and per-layer input construction agree structurally with that source; this does not certify all kernel reductions.

The precision adapters use actual operator groups and positions from the current capture, with complete per-layer/event coverage checks. They do not select printed numbers or text positions as training targets. Multi-column products use rounded BF16 operands and FP32 accumulation; single-column paths use the declared F32 policy. Batched single-column FFN work is a qualified runtime approximation, not bit identity to every separate native GEMV. The projection adapter scopes its interception around keys/attention/third calls, leaving the separate FFN adapter intact. FP16 cache conversion and BF16 product rounding receive identity-through-rounding derivatives. Those derivatives are explicit surrogate choices; true rounded execution is discrete.

Retained evidence already prevents treating this as an exact native derivative. The complete FFN precision comparison improved finite-response cosine to0.315 while increasing squared prediction error by11.272%; its local STE cosine remained0.0182. The later CUDA operand attribution found matching native BF16 normalization codes and finite local residual cosine0.99762, while the original local STE cosine was−0.01655. This isolated a real rounded-product response limitation in that retained transition. These are historical, bounded findings; they do not prove the current joint70 direction is harmful, and they are not repaired merely by routing all70 gradients. They remain an unresolved limitation of the current computational-to-weight mapping.

History and correspondence are held during the reverse/JVP calculations. The native generation subsequently refreshes both. This differentiates the connected computation on one actual observed numerical history; it does not differentiate discrete token selection or the correspondence algorithm. Tokens supply model inputs, positional geometry and provenance here. They are not loss labels. Whether the correspondence truly aligns the relevant correct/wrong computation belongs to root's separate reference audit.
