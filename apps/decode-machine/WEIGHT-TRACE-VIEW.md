# Connected weight-edit comparison

This extension joins the existing Decode Machine through **Weight edit traces** in its masthead. It uses the existing pale ground, slate structure, amber stored-weight marks and Manrope type. It is a local extension, not a replacement visual identity.

Purpose: let Marcos and an inspecting model see the same recorded before/after transformation, trace it to its source, and keep repaired, preserved and damaged responses visible together. The source is a separate native llama.cpp BF16 experiment, explicitly identified; it is not the QGRE replay or the illustrated France simulation.

The first view contains four outcome selectors, the physical calculation and reference-point expectation, a shared-history scrubber, and one connected boundary plot. The plot uses a fixed vertical scale across all four cases: relative change of the recorded vector, not an inferred probability or a recovered latent shape. The first projection's graph operands are verified; later plotted boundaries summarize the intervening computation. The original trace is the zero-change baseline and the edited trace shows the measured displacement from it.

Selecting a prediction reveals the common incoming text, both chosen tokens and their saved vocabulary scores. The first different token is still a matched-input decision. No later internal measurement is shown as a matched pair. Complete continuations remain available as separate branches. Capture identity, graph nodes, events, tensor offsets and checkpoint identities remain available in the relational evidence download.

One playback control walks the common history over a chosen total duration. Reduced motion uses a single-step action. The phone layout preserves full graph label sizes in a horizontally scrollable route rather than shrinking every stage into unreadable text.

Acceptance: case selection, scrubber, first-change navigation, playback duration, reduced motion, provenance disclosure and evidence download work. Loading/error states are visible. The native source export must qualify capture fidelity and shared histories before the UI accepts it.
